# X AIアシスタント

WordPress記事の投稿文作成、ハッシュタグ生成、予約、Xへの自動投稿を行う専用プラグインです。Xへの送信以外に外部APIを使わず、追加のAI API料金は発生しません。

## バージョン2.1.0（最終版）

標準の投稿文は次の形式です。

```text
ブログ更新しました。
ご興味ある方は、読んでみてください。

{title}

{url}

{hashtags}
```

### 記事編集画面

- 記事単位でX投稿をON／OFF
- 記事専用の投稿文を設定
- 実際に送信される文章をプレビュー
- Xへの投稿日時を予約
- X投稿済みIDを表示

### WordPress内での投稿文生成

- `{title}`：記事タイトル
- `{excerpt}`：記事の抜粋。未入力なら本文から生成
- `{url}`：記事URL
- `{hashtags}`：記事タグとカテゴリーから最大5件
- `{categories}`：カテゴリー名

AIによる文章生成、外部検索、外部ハッシュタグAPIは使用しません。

### X連携

- 下書き・予約投稿から初めて公開されたタイミングを検知
- OAuth 1.0aでX API v2の`POST /2/tweets`へ投稿
- 投稿成功・エラー・予約登録のログを保存
- 二重投稿と同時実行を防止
- SodiumまたはOpenSSLで認証情報を暗号化保存
- 確認画面付きの実投稿テスト

### 月980円以内を目指す安全上限

- テスト投稿を含むX APIへの送信試行を、月20回までに制限
- 上限到達後はX APIへ通信する前に停止
- 管理画面に今月の使用回数と残り回数を表示
- サイトのタイムゾーンを基準に、月が変わると自動で利用枠を更新

現在のURL付き投稿料金（1回0.20米ドル）では、最大約4米ドルの目安です。X側の料金変更、為替、税金、ほかのアプリによるAPI利用はプラグインから取得しないため、X Developer Consoleでも利用上限を5米ドルに設定し、自動チャージをOFFにしてください。

## インストール

リリースZIPをダウンロードし、WordPress管理画面の「プラグイン → プラグインを追加 → プラグインのアップロード」からインストールします。または、このフォルダを`wp-content/plugins/x-ai-assistant`へ配置してください。

有効化後、「設定 → X AIアシスタント」を開いて認証情報を入力します。X開発者アプリには読み取り・書き込み権限が必要で、アクセストークンは投稿先のXアカウントに対応している必要があります。

## 使い方

1. 「設定 → X AIアシスタント」で共通テンプレートとX API認証情報を保存します。
2. 記事編集画面の「X AIアシスタント」パネルを確認します。
3. 必要に応じて記事専用の投稿文や予約日時を指定します。
4. 記事を公開します。

初回更新時は、当月の成功ログを月間利用数へ反映します。通信失敗の可能性も含めて安全側に計算するため、Ver2.1.0以降はX APIへ送信を試みた時点で利用枠を1回消費します。

予約にはWordPress Cronを使用します。予約時刻を過ぎた後、サイトへのアクセスを契機として処理されるため、アクセスが少ないサイトでは多少遅れる場合があります。

## Git Updater

メインのプラグインファイルには、Git Updaterが読み取る次の必須ヘッダーを設定しています。

```text
GitHub Plugin URI: https://github.com/healingyasu/x-ai-assistant
Primary Branch: main
Release Asset: true
```

タグをGitHubへ送信すると、GitHub Actionsが`x-ai-assistant.zip`を生成してリリースへ添付します。

## セキュリティ

- 認証情報をリポジトリへ保存しません。
- パスワード入力欄へ保存済みの値を再表示しません。
- 設定変更とテスト投稿には、権限確認とWordPressのnonce検証が必要です。
- 入力値を無害化し、画面出力をエスケープします。
- Xへの通信にはWordPressの安全なHTTP APIを使い、リダイレクトを許可しません。
- WordPressの`AUTH_KEY`から生成した鍵で認証情報を暗号化します。

WordPressのソルトを変更した場合は、認証情報を再入力してください。SodiumとOpenSSLのどちらも利用できない環境では、認証情報を保存しません。

## 今回の対象外

関連ジャンル検索、フォロー・いいね候補、返信文の生成などの交流支援は含みません。交流操作を実装する場合も、人間が候補を確認して選択する設計とします。
